# Security headers & the API gate

## What is sent

| Header | Value | Protects against |
|---|---|---|
| `Strict-Transport-Security` | 2 years, `includeSubDomains` (no `preload`) | downgrade to plain HTTP |
| `X-Content-Type-Options` | `nosniff` | an uploaded "image" being executed as a script |
| `X-Frame-Options` | `DENY` | clickjacking (embedding the app in another site) |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | leaking booking ids / filters in URLs |
| `Permissions-Policy` | camera, microphone, geolocation, payment, usb off | abuse of browser features the app never uses |
| `X-Powered-By` | removed | advertising the framework |
| `Content-Security-Policy` | see below | cross-site scripting (XSS), data exfiltration |

Static headers come from `next.config.ts`; the CSP is built per request by Clerk from `lib/security/headers.ts` (`proxy.ts` passes it to `clerkMiddleware`).

## The CSP

`strict: true` → `script-src 'self' 'nonce-<random per request>' 'strict-dynamic'`. Only scripts that carry this request's nonce (or are loaded by one that does) may run, so an injected `<script>` or inline handler is refused. Clerk's default allows `https:` for scripts, which makes a CSP nearly useless; strict mode removes that.

Allowed beyond `'self'`: Clerk (its defaults + your frontend domain, derived from the publishable key), Google Maps (script, `maps.googleapis.com`, `maps.gstatic.com`), Supabase (`*.supabase.co` for payment-proof images), Google fonts for the Places widget. `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`.

### It starts in REPORT-ONLY mode

The browser logs what *would* be blocked but blocks nothing, so nothing can break. To enforce, after a clean click-through:

1. Vercel → Settings → Environment Variables → `CSP_ENFORCE=true`, redeploy.
2. To roll back, remove the variable and redeploy.

### Required change to `app/layout.tsx` (patches/app-layout.patch)

A nonce exists only per request, and two scripts must be given it: Clerk's loader and the theme script. Without this, enforcing would break sign-in and dark mode.

```tsx
import { headers } from "next/headers"
export default async function RootLayout(...) {
  const nonce = (await headers()).get("x-nonce") ?? undefined
  return (
    <ClerkProvider dynamic>            // was <ClerkProvider>
      ...
      <ThemeProvider nonce={nonce}>{children}</ThemeProvider>   // was <ThemeProvider>
```

**Trade-off:** every page is now rendered per request (no static caching) — including `/`, `/packages`, `/privacy`, `/terms`. Fine at this scale; it is what makes per-request nonces possible.

## The `/api` gate (proxy.ts)

Signed-out requests to any `/api/*` route get `401 {"error":"Unauthorized"}` before route code runs, except the public allow-list already in your proxy (`/api/webhooks`, `/api/vendor-brief`, `/api/public`). Each route still checks the *role* itself. A route added tomorrow without a guard is no longer open to the internet.

## What was verified, and what was not

Verified in a production build served locally, over real HTTP: all static headers present; `X-Powered-By` absent; `Content-Security-Policy-Report-Only` present with a fresh nonce; **every `<script>` on `/`, `/terms`, `/privacy`, `/packages`, `/support`, `/forgot-password`, `/sign-in`, `/staff-login` carries that nonce**; signed-out `/api/bookings` → 401 with the headers; `/api/public/packages` → 200; `/api/webhooks/clerk` reachable. 40 automated tests cover the gate, both CSP modes, and the header values (the CSP is generated by Clerk's own builder).

**Not verified (I cannot run your Clerk, Google Maps or Supabase):** that sign-in, the map, and image previews produce no CSP violations. That is what the checklist below is for.

## Click-through checklist (browser DevTools open → Console; violations read "Content Security Policy … would be blocked" in report-only mode)

Do it in a normal window with a real sign-in.

- [ ] `/sign-in` and `/staff-login`: page loads, sign in succeeds
- [ ] Console: no CSP messages after sign-in
- [ ] Client: create a booking → the venue box autocompletes and shows the map suggestions
- [ ] Client: upload a payment proof → the preview image shows; submit works
- [ ] Admin: open a payment → the proof image loads
- [ ] Dark/light toggle (press `d`) works and does not flash on reload
- [ ] Reports (charts render), audit trail, integrity page
- [ ] Export CSV downloads
- [ ] Sign out, sign back in

If a message names a source, add it to `lib/security/headers.ts` (`directives`) and re-test. When the console is clean, set `CSP_ENFORCE=true`.
